**UML process (for everyone)**
1. **Before coding**, Members 1 and 2 sketch the Stage 1 class and sequence diagrams, and the team agrees on them in one short meeting. This sets the method signatures between packages.
2. Each member updates their own package's classes in the class diagram as they code.
3. Save diagrams in `docs/uml/` as `stage-1-class` and `stage-1-sequence`.
4. Before tagging, Members 1 and 2 check that the diagrams match the code.
5. At Stage 3, update the same files. The final class diagram must match the Stage 3 code, and the final sequence diagram must include a VIP or Happy Hour behaviour.

Use a text-based tool like PlantUML or Mermaid, so the diagrams live in Git as `.puml` or `.md` files and merge cleanly. Exported PNGs or `.drawio` files are binary or XML blobs, so two people editing them at once will cause painful conflicts. If you use draw.io anyway, give each diagram a single owner.

Member 5 and Member 4 carry the most Stage 2 and 3 integration work later (Host, Happy Hour, new customer types in the controller and CLI). If the load feels uneven, shift `ObjectiveChecker` or `StateDisplay` to Member 3, who has the lightest coding load.
